## الإصلاحات المنفذة

### 1) لوحة الأدمن — بناء مكسور (P0)
- **الجذر**: `src/styles.css` يستورد `./tailwind.css` والملف غير موجود →
  فشل Vite: `ENOENT tailwind.css`.
- **الإصلاح**:
  - إنشاء `admin_dashboard/src/tailwind.css` بطبقة `@tailwind base/components/utilities`.
  - `tailwind.config.ts`: كانت الألوان تُقرأ بغلاف `hsl(var(--x))` بينما `styles.css`
    يعرّفها كألوان مباشرة → نزع الغلاف (`var(--x)` مباشرة) فيعمل الوضعان
    الداكن والفاتح معًا بلا قيم فارغة.
- **التحقق**: `npm run build` ✅ (tsc نظيف + dist كامل).

### 2) المراسلة — ضياع الرسائل عند طفو السيرفر (P0)
- **الجذر**: `MessageSender.saveOptimisticLocally` يحفظ العرض المتفائل ويبثّه
  للواجهة لكنه **لا يكتب في `outbox_messages`** — `OutboxRetryWorker` لا يرى
  الرسالة فلا يعيد إرسالها عند موت العملية/انقطاع الشبكة قبل `SERVER_ACK`.
- **الإصلاح** (`core/MessageSender.kt`):
  - كل رسالة فردية صادرة تُكتب الآن في `outbox_messages` عبر
    `OutboxMessageEntity.create(id=clientId, idempotencyKey=clientId,
    targetRedId=peer)` — فهرس unique على idempotencyKey يمنع الشبح الثاني.
  - `OutboxRetryWorker.schedule(context)` فور الإدراج → إرسال فوري أو retry أسي
    حتى `SERVER_ACK` الذي يُنهي الصف في `RedConnectionService` (المسار القائم).
  - المجموعات مستثناة عمدًا: لها redrive مخصص (`red_group_outbox` +
    `MessageRecoveryWorker`) — لا قناة إعادة إرسال مزدوجة.
  - فشل إدراج الـoutbox لا يُفشل العرض المتفائل (العمال الدوريون يغطونه).
- **التحقق**: `:app:compileDebugKotlin` + `testDebugUnitTest` ✅.

### 3) المراسلة — «زر الإرسال لا يظهر» (UX)
- **الجذر**: `SovereignChatInputBar` يجعل زر الإرسال معطّلًا رماديًا حتى أول
  حرف فيبدو مفقودًا، والقياس 46dp دون حد اللمس المريح.
- **الإصلاح**: زر إرسال **دائم الظهور** بنمط واتساب، مفعّل لحظة وجود نص،
  48dp، تباين واضح في حالتي التمكين/التعطيل، مع بقاء زر الصوت بجانبه دائمًا.

### 4) المراسلة — التحقق من ظهور الرسالة (بدون تغيير — مسار سليم موثق)
- `DecryptedMessageBus.messages` يُجمَع في `ChatHubScreen` (سطر 857) ويضيف
  الرسالة المتفائلة فورًا؛ الاستعادة من Room تغطي إعادة التشغيل.
- دورة الحالات `SENDING → QUEUED → SERVER_ACK → DELIVERED → READ` idempotent
  عبر `MessageAckBus` + `updateMessageStatus` بنفس المعرف (لا تكرار ولا فقده).

### 5) المنشورات والحالات — القص الصامت إلى محتوى مزروع (P1)
- **الجذر**: `FeedViewModel.load` عند أي فشل API يمسح المنشورات الحقيقية
  ويزرع منشورين وهميين — المستخدم يظن أن منشوراته اختفت.
- **الإصلاح** (`social/FeedViewModel.kt` + `ui/FeedScreens.kt`):
  - فشل الشبكة مع وجود منشورات محمّلة سابقًا → تبقى معروضة + رسالة
    «تعذر التحديث — تُعرض آخر نسخة محملة».
  - فشل مع فراغ → حالة `FeedState.Error` صريحة بنص السبب + زر «إعادة المحاولة»
    في الشاشة (كان موجودة لفرع الخطأ، أضيف للفراغ النظيف).
  - البذور المزروعة اثنتان → بذرة ترحيبية واحدة معرّفة، لا تخفي فشل الاتصال.

### 6) المكالمات — توحيد واجهات المتصل/المستلم (P1)
- **الجذر**: `ModernRedDashboard` كان يعرض `UnifiedCallOverlaysModern` — نسخة
  مبسطة تكرارية (CallOverlayModern/ActiveCallScreenModern بنصوص ثابتة) بدل
  الواجهات الحية الكاملة للأنواع التسعة، فالمكالمة الفردية تفقد الفيديو/PiP/الكاميرا.
- **الإصلاح** (`calls/UnifiedCallOverlays.kt`): `UnifiedCallOverlaysModern` أصبح
  يفوّض إلى `UnifiedCallOverlays` — الطبقة الموحدة ذات الأولوية الواحدة:
  1:1 (YounesCallOverlay → ActiveCallScreen بحلقة النبض والفيديو الحي وPiP
  والرد على المكالمة الثانية) > Zoom (≤100) > جماعية (شبكة المشاركين ≤32) >
  مؤتمر/مساحات > بث مباشر، مع `MinimizedCallBar` الموحد و`SecondIncomingBanner`.
  المنسق الموحد `UnifiedCallOrchestrator` والخدمات تبقى كما هي (عقد صحيح).
- **التحقق**: `:app:compileDebugKotlin` ✅.

### 7) Docker — ملفات override مكسورة (P1)
- **الجذر**: 4 من 5 ملفات override تحيل لشبكة/خدمات غير معرّفة داخلها، فيفشل
  `docker-compose -f base -f override config` ويمنع التشغيل المركّب:
  - `dev.yml`: `pgadmin` → شبكة `red-net` غير معرفة في الملف.
  - `staging.yml`: `prometheus` → نفس المشكلة.
  - `observability.yml`: `postgres-exporter` يعتمد `db-postgres` المعرّف في الأساس فقط
    مع إعادة تعريف شبكة متضاربة (`enable_ipv6: false` يكسر الـmerge).
  - `prod.yml`: `nginx-exporter` يعتمد `nginx` من الأساس + إعادة تعريف شبكة
    بشبكة فرعية IPAM تتعارض مع الأساس عند الـmerge.
- **الإصلاح**: حذف إعادة تعريف الشبكة من الملفات الأربعة (join عبر الأساس)،
  مع تعليق يوثق السياسة.
- **التحقق**: `docker-compose -f docker-compose.yml -f <override> config --quiet`
  ✅ للخمسة جميعًا (كان: 4 إخفاقات).
- **nginx.conf و.env.example**: مُدقّقان — مسارات الـWebSocket التسعة/sfu/الصحة
  سليمة، والبورتات (8088→80، 8443→443، SFU 4000+40000-40100/udp، TURN
  3478/5349/443/80+45000-45050) متسقة مع compose و`README.md`؛ لا تغيير مطلوب.
