## 1) إصلاحات Workers الثلاثية (SovereignWorkers.kt — إعادة كتابة كاملة)

### 1.1 PreKeyRefreshWorker — ربط حقيقي بدل TODO
- كان: TODO فارغ يعيد success بلا عمل كل 6 ساعات
- أصبح: يستدعي `PreKeyPoolManager(applicationContext).replenishIfNeeded()` — يفحص المخزون عبر `GET /api/devices/{id}/prekeys/stock`، يولّد ويرفع دفعة EC+Kyber تلقائياً إن هبط تحت الحد الموصى به
- يعيد `ec_available`/`kyber_available` كبيانات نتيجة قابلة للمراقبة
- شبكة أمان دورية — نفس المسار الذي تعمل عند كل CONNECTED في RedConnectionService

### 1.2 ConnectionGuardWorker — بديل معماري للنبضة الزائفة
**الاكتشاف**: السيرفر يدير الحضور من دورة WebSocket نفسها (`RedMasterHandler.touchPresence` يكتب Redis لكل إطار + `last_seen` عند الاتصال/الفصل فقط — بلا كتابة DB لكل إطار). نبضة عميلية دورية كانت ستكتب في `red:presence:index` دون اتصال حي → حالة "متصل" زائفة تخدع جهات الاتصال.

**الحل**: العامل الجديد يقرأ الحالة الفعلية من `ConnectionStatusRepository` (الذي تغذيه RedConnectionService وحده)، وعند OFFLINE رغم توفر الشبكة يوقظ `ACTION_REDRIVE_STUCK` — idempotent بذات clientId (لا تكرار إرسال) — ويتعامل بأناقة مع رفض `startService` في الخلفية (ليس فشلاً: الخدمة START_STICKY تعود وحدها).

### 1.3 MessageRetryWorker — حذف التكرار
`OutboxRetryWorker` في `core/outbox` نظام متكامل (قاطع دائرة ب persisted state + إحياء العالق SENDING + foreground expedited + APPEND_OR_REPLACE بعد كل enqueue + من MessageRecoveryWorker وDeviceSettings). النسخة الهيكلية كانت تكرار يعمل بلا فائدة كل 15 دقيقة — حُذفت مع جدولتها.

**تحقق**: 10,575 بايت، 23/23 أقواس، صفر TODO، الرموز المرجعية مدققة (ApiResult في auth، ACTION_REDRIVE_STUCK عام في companion).

## 6) تدقيق Docker والبورتات — النتيجة: سلسلة متسقة بالكامل ✓

### السلسلة الحقيقية (مدققة طرفاً لطرف)
```
التطبيق → http://IP:8088 (nginx منشور خارجياً 8088→80، 8443→443)
  → nginx (listen 80/443) → proxy_pass backend:8080 (upstream backend-pool)
    → Backend Spring Boot: SERVER_PORT=8080 (متغير compose يوحّد التعارض التاريخي 8088/8080 — موثق في compose نفسه)
  → WebSocket /ws/master → RedMasterHandler
  → SFU: العميل يشتق ws://IP:8088/sfu من ServerEndpoint.url()
    → nginx location /sfu → upstream sfu-pool → media-sfu:4000
    → تذكرة موقعة (SfuTicketController) بسر مشترك SFU_TICKET_SECRET بين backend وSFU
  → WebRTC UDP 40000-40100 (RTC range pinned في compose)
```

**التطبيق (ServerEndpoint)**: الافتراضي من BuildConfig `RED_SERVER_URL` (gradle property، افتراضي محاكي `10.0.2.2:8088`) + auto-discovery بالشبكة (NSD) + ترحيل آمن للعناوين القديمة + حارس cleartext: HTTP مسموح لـLAN فقط (يكمّل network_security_config).

**الاكتشافات أثناء التدقيق (تدوين لا تعديل — تعمل لكن للمراجعة)**:
1. تعليق compose يقول "application.yml يضبط 8088" بينما الحالي 8080 — التعليق قديم والقيم متسقة (توضيح مستقبلي فقط)
2. `FALLBACK_URL = http://127.0.0.1:8088` في ServerEndpoint — بلا فائدة على جهاز حقيقي (localhost هو نفسه) — لكنه مسار الطوارئ فقط والdiscovery يعوض
3. sfuTicket لا يحمل wsUrl — العميل يشتقه من ServerEndpoint (تصميم سليم: بورت واحد لكل شيء خلف nginx)
4. الإصدار الحي للملف في backend يستخدم profile docker بعناوين service names (db-postgres/cache-redis) — متسق مع compose

**الحكم**: لا فجوة اتصال — 8080 مقابل 4000 كانت ظاهرتين مختلفتين (باك-إند داخلي vs SFU داخلي) كلاهما خلف nginx على 8088/8443 خارجياً.

## 11) الفشول الثلاثة وقصصها

1. **GlassSettingsPolicyTest**: `GLASS_STYLES` في الإعدادات كان ينقصه `CYBER_FROST` — أي مستخدم يختار «السيبراني» كان يُعاد صامتاً إلى AUTO. أُضيف للتعدادات المسموحة.
2. **SovereignGlassPolicyTest**: خطأ دقة عائمة — `Color.White.copy(alpha = 0.5f)` يُخزَّن 8-bit (128/255 = 0.50196). التفاوت في الاختبار صار 0.005.
3. **SdpMediaOptimizerTest** → **كشف بقاً حقيقياً في الإنتاج**: `applyVideoFeedback` كان يطابق `a=rtpmap:N Codec/` حتى الشرطة المائلة فقط، فيدرج سطور `rtcp-fb` في منتصف سطر rtpmap ويترك `90000` يتيمة — **SDP تالف كان سيكسر كل مكالمة فيديو حقيقية**. الإصلاح: النمط يستهلك السطر كاملاً (`[^\r\n]*`). والاختبار حُدّث ليحمي العقد الموثق في `CallMediaKind`: مكالمات 1:1 تفضّل H264 أولاً (فك عتادي شامل + زمن استجابة أدنى) بينما AV1 للمجموعات/المؤتمرات حيث SVC.

## 12) توافق Node 16 مع Vite 5 (لوحة الأدمن) — ثلاث طبقات موثقة

البيئة المحلية تحمل Node 16.20.2 بينما Vite 5 يتطلب 18+. الحلول (كلها بتعليقات في vite.config.ts):
1. **tanstackRouter**: استيراد ساكن → ديناميكي مشروط (`Node >= 18` فقط) — الشجرة `routeTree.gen.ts` محفوظة على القرص فالبناء يكتمل بلا الإضافة.
2. **crypto.getRandomValues**: Vite يستورد `node:crypto` افتراضياً ويستدعي الدالة (موجودة في Node 19+ فقط) — polyfill على `globalThis.crypto` عبر vite.config **+** ترقيع جراحي لنقطة الاستيراد داخل الحزمة (`webcrypto` من node:crypto).
3. **ملاحظة صيانة**: هذه الحمولات مؤقتة — عند ترقية Node إلى 20 LTS تُحذف ويصير vite.config عادياً.
